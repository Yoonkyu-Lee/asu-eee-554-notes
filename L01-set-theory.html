이 모듈이 하는 일

What this module does

한 줄 요약: "질문"을 "집합"으로 바꾸는 법을 배운다.

The one-line version: learn to rewrite a question as a set.

이 모듈에는 확률이 거의 안 나와. 슬라이드 40장 중 확률 기호 P(·)가 등장하는 건 딱 한 번이야. 그래서 노잼으로 느껴지는 게 정상이야. 목적이 다르거든.

There is almost no probability in this module. Across all 40 slides the symbol P(·) appears exactly once. If that makes it feel like a slow start, it is one, deliberately. This module is doing setup work.

확률론이 답하고 싶은 건 "이 일이 일어날 가능성은 얼마인가"인데, 그러려면 먼저 "이 일"이라는 게 수학적으로 뭔지 못 박아야 해. 그 정의가 바로 집합이야. 이 모듈은 확률을 계산하는 법이 아니라, 확률이 올라탈 도로를 까는 단계야.

Probability answers one kind of question: how likely is this? But nothing can be computed until "this" has a precise mathematical form. Sets are that form. So none of this module is about calculating a probability. It is about laying the track that probability will later run on.

이 모듈에서 새로 나오는 단어들: sample space, event, power set, countable / uncountable, index set, partition.
이 중 countable과 partition 두 개가 나중에 결정적으로 쓰여. countable은 Module 2에서 σ-algebra가 왜 필요한지를 결정하고, partition은 Module 3의 law of total probability와 Bayes 정리가 통째로 그 위에서 돌아가. 나머지는 도구야.
New vocabulary here: sample space, event, power set, countable / uncountable, index set, partition.
Two of them do real work later. Countable is what forces a σ-algebra to exist at all in Module 2, and partition is the foundation under both the law of total probability and Bayes' theorem in Module 3. The rest are tools you reach for as needed.

01

Probability vs Statistics

화살표 방향이 반대인 두 학문.

Same picture, arrow reversed.

핵심 대비

Probability: 불확실성의 수학적 모델에서 출발해서, 여러 결과가 나올 가능성을 분석한다.  Model → Data

Statistics: 관측된 데이터에서 출발해서, 그 밑에 깔린 확률 모델이나 미지의 파라미터를 추론한다.  Data → Model

The contrast

Probability: start from a mathematical model of uncertainty, work out how likely each outcome is.  Model → Data

Statistics: start from observed data, work back to the model underneath it or to its unknown parameters.  Data → Model

예제 1.1

다음 질문이 probability인지 statistics인지 판정해.

  1. 패킷 손실률이 정확히 0.1인 링크에서, 10개를 보내면 정확히 2개가 깨질 확률은?
  2. 어떤 링크로 1000개를 보냈더니 87개가 깨졌다. 이 링크의 손실률은 얼마인가?
  3. 공정한 동전 100번 던져서 앞면이 70번 이상 나올 확률은?
  4. 동전 100번 던져서 앞면이 70번 나왔다. 이 동전은 공정한가?
풀이

1, 3번이 probability. 모델(손실률 0.1 / 공정한 동전)이 먼저 주어졌고 데이터의 가능성을 계산해. 2, 4번이 statistics. 데이터가 먼저 있고 모델을 되짚어. 판별법은 간단해. "~라면"이 문장 앞에 붙으면 probability, "~였는데"가 붙으면 statistics.

재밌는 건 3번과 4번이 사실상 같은 계산을 쓴다는 거야. 통계에서 하는 가설검정은 "공정하다고 가정했을 때 이 데이터가 나올 확률"(= 3번)을 계산해서, 그게 너무 작으면 가정을 버리는 방식이거든. 그래서 statistics는 probability를 도구로 써.

Example 1.1

Decide whether each question is probability or statistics.

  1. On a link whose packet loss rate is exactly 0.1, you send 10 packets. What's the chance exactly 2 are dropped?
  2. You sent 1000 packets over some link and 87 were dropped. What is that link's loss rate?
  3. You flip a fair coin 100 times. What's the chance of 70 or more heads?
  4. You flipped a coin 100 times and got 70 heads. Is this coin fair?
Solution

1 and 3 are probability: the model is given up front, a loss rate of 0.1 or a fair coin, and you work out how likely the data is. 2 and 4 are statistics: the data is given and you work back to the model. Quick test: a question that opens with "if" is probability. One that opens with "I observed" is statistics.

Worth noticing: 3 and 4 run almost the same arithmetic. A hypothesis test computes the probability of the observed data under the assumption that the coin is fair, which is exactly question 3, then discards the assumption when that number comes out small enough. Statistics runs on probability as its engine.

함정

"statistics가 probability의 상위 과목"이 아니다

둘은 위아래 관계가 아니라 화살표 방향이 반대인 관계야. 이 과목(554)은 화살표 위쪽만 다뤄. 데이터에서 모델을 추정하는 얘기는 여기서 안 나와. 그래서 "실제 데이터가 하나도 안 나오네?"라고 느끼는 게 맞아. 이 과목은 원래 그래.

"확률은 빈도다"라고 정의하면 막힌다

"많이 던져보면 1/2에 수렴하니까 확률이 1/2"이라는 설명은 직관적이지만 정의로는 못 써. 순환논법이거든. "수렴한다"는 것 자체가 확률의 개념을 이미 쓰고 있어. 그래서 Module 2에서 확률을 빈도가 아니라 세 개의 공리를 만족하는 함수로 정의해. 이 과목의 확률은 처음부터 끝까지 공리적 정의야.

Trap

Statistics is not probability, level 2

Neither one sits above the other. The arrow simply runs the other way. This course covers the top arrow only. Inferring a model from data never appears. So the feeling that you never see any real data is accurate, and it is the scope, not an oversight.

Frequency is not a usable definition

Flip it enough and it settles near 1/2, so the probability is 1/2. Intuitive, but it cannot serve as the definition, because "settles near" already assumes what probability means. Module 2 steps around this by defining probability as any function satisfying three axioms. Nothing in this course rests on frequency.

02

왜 집합인가

Why sets

질문 → 사건 → 확률. 그리고 AND/OR/NOT ↔ ∩/∪/ᶜ.

Question → event → probability. And AND/OR/NOT ↔ ∩/∪/ᶜ.

공정한 주사위를 굴리는 실험을 생각해. 가능한 결과 전체를 모은 게 표본공간(sample space) Ω야.

Take the experiment of rolling a fair die. Collect every outcome it can produce and you have the sample space Ω.

Ω = {1, 2, 3, 4, 5, 6}

이제 우리가 던지고 싶은 질문들을 보자. 놀라운 건, 모든 질문이 Ω의 부분집합 하나로 정확히 대응된다는 거야.

Now look at the questions you actually want to ask about that roll. Every single one of them lands on exactly one subset of Ω.

정의

Ω의 부분집합을 사건(event)이라고 부른다. 결과 ω가 나왔을 때 ω ∈ A이면 "사건 A가 일어났다"고 말한다.

Definition

A subset of Ω is called an event. If the outcome that came up is ω and ω ∈ A, we say "event A occurred".

질문을 조합하면 집합 연산이 된다

Combining questions gives you set operations

여기가 진짜 핵심이야. 질문을 말로 조합하면, 집합에서는 연산으로 자동 번역돼.

This is the part that matters. Combine two questions in plain words and the set side translates it into an operation for free.

말로 하는 조합집합 연산주사위 예 (A=짝수, B=3 초과)

ECE 385/391 했으면 이건 이미 아는 거야. Boolean algebra랑 정확히 같은 구조거든. AND는 &, OR는 |, NOT은 ~. 실제로 Ω의 원소가 n개면, 각 사건은 n비트 마스크 하나랑 1:1로 대응돼. 집합 연산 = 비트 연산. 07번 섹션에서 이걸 그림으로 확인할 거야.
If you have taken ECE 385 or 391, you already know this. It is the same structure as Boolean algebra, symbol for symbol. AND is &, OR is |, NOT is ~. When Ω has n elements, every event corresponds one to one with an n-bit mask, and set operations are bit operations. Section 07 shows this as a picture.
함정

다른 질문이 같은 사건일 수 있다

"짝수인가?"와 "2, 4, 6 중 하나인가?"는 말은 다르지만 같은 사건이야. 둘 다 {2,4,6}이거든. 확률은 사건에만 붙지 질문의 표현에는 안 붙어. 그래서 P는 "질문의 함수"가 아니라 "집합의 함수"야. 시험에서 말로 길게 서술된 사건이 나오면 일단 원소를 나열해서 집합으로 바꾸고 시작해.

Ω를 안 정하고 시작하면 다 틀린다

Ac는 Ω가 뭔지 정해져야만 의미가 있어. A={2,4,6}일 때 Ω={1,…,6}이면 Ac={1,3,5}지만, Ω={1,…,8}이면 Ac={1,3,5,7,8}이야. 문제를 읽자마자 Ω부터 적어라. HW1 Problem 1이 Ω={1,…,8}로 시작하는 게 우연이 아니야. 주사위 습관 때문에 6까지로 착각하라고 낸 함정이야.

Trap

Two different questions can be the same event

"Is it even?" and "is it one of 2, 4, 6?" are worded differently but are the same event. Both are {2,4,6}. Probability attaches to the event, never to how the question was phrased, which is why P is a function of sets and not a function of sentences. When an exam hands you an event buried in a paragraph of words, list the elements and turn it into a set before you do anything else.

Skip Ω and everything after it is wrong

Ac means nothing until Ω is fixed. With A={2,4,6}: if Ω={1,…,6} then Ac={1,3,5}, but if Ω={1,…,8} then Ac={1,3,5,7,8}. Write down Ω the moment you finish reading the problem. HW1 Problem 1 opening with Ω={1,…,8} is not an accident. It is baited for anyone whose die reflex stops at 6.

집합의 기초

Set basics

Definition 1–5. 표기법 두 가지, 그리고 같음 · 포함 · 공집합 · 서로소.

Definitions 1–5. Two notations, then equality, inclusion, the empty set, disjointness.

Definition 1

집합(set)은 서로 구별되는 대상들의 모임이고, 그 대상들을 원소(element)라고 한다.

Definition 1

A set is a collection of distinct objects, and those objects are its elements.

표기법 두 가지

Two ways to write a set

METHOD 1 — LISTING
Ω = {1, 2, 3, 4, 5, 6}

그냥 다 적는다. 원소가 적고 유한할 때만 가능.

Just write them all out. Only works when the set is finite and small.

METHOD 2 — SET BUILDER
Ω = {ω ∈ ℤ : 1 ≤ ω ≤ 6}

"ω가 ℤ에 속하는데(∈), 단(:) 1 이상 6 이하인 것들". 무한집합도 쓸 수 있다.

Read it as "the ω in ℤ (∈) such that (:) 1 ≤ ω ≤ 6". This one also works for infinite sets.

콜론 :은 "such that"으로 읽어. 어떤 교재는 |를 쓰기도 하는데 같은 뜻이야.

The colon : reads as "such that". Some books write | instead. Same thing.

같음 · 포함 · 공집합 · 서로소

Equality, inclusion, empty, disjoint

Definition 2 — Equality

A = B ⟺ 두 집합이 정확히 같은 원소를 가진다. 즉 ∀ω : ω ∈ A ⟺ ω ∈ B

Definition 2 — Equality

A = B ⟺ the two sets hold exactly the same elements. That is, ∀ω : ω ∈ A ⟺ ω ∈ B

Definition 3 — Subset

A ⊆ B ⟺ A의 모든 원소가 B에도 있다. 즉 ∀ω : ω ∈ A ⟹ ω ∈ B

Definition 3 — Subset

A ⊆ B ⟺ every element of A is also in B. That is, ∀ω : ω ∈ A ⟹ ω ∈ B

Definition 4 — Empty set

∅ = { }. 원소가 하나도 없는 집합.

Definition 4 — Empty set

∅ = { }. The set with no elements at all.

Definition 5 — Disjoint

A와 B가 서로소(disjoint)라는 건 겹치는 원소가 없다는 뜻. 즉 A ∩ B = ∅

Definition 5 — Disjoint

A and B are disjoint when they share no element. That is, A ∩ B = ∅

예제 3.1

Ω = {1, 2, 3, 4, 5, 6, 7, 8}이고 A = {ω ∈ Ω : ω는 3의 배수}, B = {ω ∈ Ω : ω > 5}일 때, 두 집합을 나열법으로 쓰고 서로소인지 판정해.

풀이

A = {3, 6}, B = {6, 7, 8}. A ∩ B = {6} ≠ ∅이므로 서로소가 아니다.

참고로 Ω가 {1,…,8}로 한정된 게 중요해. 만약 Ω = ℤ였다면 A = {…, −3, 0, 3, 6, 9, …}로 완전히 다른 집합이 돼.

Example 3.1

Let Ω = {1, 2, 3, 4, 5, 6, 7, 8}, A = {ω ∈ Ω : ω is a multiple of 3} and B = {ω ∈ Ω : ω > 5}. Write both sets by listing, and decide whether they are disjoint.

Solution

A = {3, 6}, B = {6, 7, 8}. Since A ∩ B = {6} ≠ ∅, they are not disjoint.

Notice how much work Ω = {1,…,8} is doing here. Had Ω = ℤ, the same description would give A = {…, −3, 0, 3, 6, 9, …}, an entirely different set.

함정 · 이 섹션에서 제일 많이 틀리는 곳

∈ 와 ⊆ 를 섞어 쓰면 안 된다

∈은 원소가 집합에 속한다는 관계이고, ⊆는 집합이 집합에 포함된다는 관계야. 왼쪽에 오는 게 뭐냐가 다름.

  • 1 ∈ Ω  ✓  (1은 원소)
  • {1} ⊆ Ω  ✓  ({1}은 집합)
  • 1 ⊆ Ω  ✗  (1은 집합이 아님)
  • {1} ∈ Ω  ✗  (Ω의 원소는 숫자지 집합이 아님)

단, {1} ∈ 2Ω는 맞아. power set의 원소는 집합이니까. 07번에서 다시 볼게.

중복과 순서는 무시된다

{1, 1, 2} = {1, 2}이고 {1, 2} = {2, 1}이야. "distinct objects"라는 정의 그대로. 순서가 중요하면 그건 집합이 아니라 튜플이야. HW1 Problem 3에서 패킷 두 번 전송하는 표본공간을 만들 때 Ω = {SS, SF, FS, FF}로 SF와 FS를 구별해서 써야 하는데, 이건 각 원소가 "순서 있는 쌍"이기 때문이야. 집합 안의 원소는 순서가 없지만, 원소 자체는 순서 있는 객체일 수 있어.

∅ 와 {∅} 는 다르다

∅은 원소가 0개. {∅}은 원소가 1개(그 원소가 마침 공집합일 뿐). 빈 상자와, 빈 상자를 담은 상자의 차이야.

∅ 는 모든 집합의 부분집합이다

∅ ⊆ A는 어떤 A에 대해서도 항상 참. 정의를 보면 "∅의 모든 원소가 A에 있다"인데 ∅에 원소가 없으니 반례를 만들 수가 없어서 자동으로 참이야 (vacuous truth). 처음엔 억지 같지만, 이게 성립해야 07번의 power set 개수 공식 2n이 맞아떨어져.

서로소 ≠ 여집합

A ∩ B = ∅이라고 해서 B = Ac인 건 아니야. 위 네 번째 그림에서 A와 B는 서로소지만, 둘을 합쳐도 Ω를 못 채우잖아. 여집합이려면 서로소이면서 동시에 둘이 합쳐서 Ω 전체여야 해. 이게 09번 partition의 예고편이야.

Trap · the highest-error spot in this section

Never mix up ∈ and ⊆

∈ relates an element to a set. ⊆ relates a set to a set. What sits on the left is what differs.

  • 1 ∈ Ω  ✓  (1 is an element)
  • {1} ⊆ Ω  ✓  ({1} is a set)
  • 1 ⊆ Ω  ✗  (1 is not a set)
  • {1} ∈ Ω  ✗  (the elements of Ω are numbers, not sets)

But {1} ∈ 2Ω is correct, because the elements of a power set are themselves sets. Section 07 comes back to this.

Repeats and order are ignored

{1, 1, 2} = {1, 2} and {1, 2} = {2, 1}. That is just "distinct objects" from the definition. When order does matter you are not holding a set, you are holding a tuple. In HW1 Problem 3 the sample space for sending two packets is Ω = {SS, SF, FS, FF}, where SF and FS have to stay separate, because each element is an ordered pair. Elements inside a set have no order, but an element itself can be an ordered object.

∅ and {∅} are not the same

∅ has zero elements. {∅} has one, and that one element happens to be the empty set. An empty box, versus a box containing an empty box.

∅ is a subset of every set

∅ ⊆ A is always true, whatever A is. The definition asks that every element of ∅ also lies in A, and since ∅ has no elements there is no counterexample available, so it holds automatically. That is a vacuous truth. It feels like a technicality at first, but the power set count 2n in section 07 only works out because of it.

Disjoint is not the same as complement

A ∩ B = ∅ does not give you B = Ac. In the fourth picture above, A and B are disjoint, yet putting them together still leaves part of Ω uncovered. For a complement you need disjoint and covering all of Ω at the same time. That is the preview of partition in section 09.

함정

합집합의 "또는"은 포함적 or 이다

A ∪ B에는 A ∩ B도 들어있어. 일상어의 "커피 또는 차"는 보통 배타적이지만, 수학의 ∪는 아니야. 위 벤 다이어그램에서 A ∪ B를 눌러보면 가운데 겹치는 부분도 같이 칠해지는 걸 볼 수 있어.

배타적 or를 원하면 대칭차(symmetric difference)를 써야 해: A △ B = (A\B) ∪ (B\A). 이게 XOR이야.

차집합은 순서가 바뀌면 다르다

A \ B ≠ B \ A. 위 예제로 확인하면 A\B = {1,2}인데 B\A = {5,6}이야. ∪와 ∩은 교환법칙이 되지만 \ 는 안 돼.

차집합은 결합법칙도 없다

A \ (B \ C) ≠ (A \ B) \ C 가 일반적으로 성립해. 반례: A={1,2}, B={2}, C={2}. 왼쪽은 B\C = ∅이라 A\∅ = {1,2}, 오른쪽은 {1}\{2} = {1}. 그래서 차집합이 여러 개 나오면 무조건 ∩ Bc로 바꿔서 풀어라. ∩와 ᶜ만 남으면 결합법칙이 다시 살아나거든.

여집합에는 숨은 인자가 있다

Ac는 사실 Ω \ A야. 즉 Ω에 의존하는 연산인데 표기에는 Ω가 안 보여. 시험에서 표본공간을 중간에 바꾸는 문제가 나오면 여기서 다 틀려. 항상 "지금 Ω가 뭐지?"를 먼저 확인해.

Trap

The "or" in a union is inclusive

A ∪ B contains A ∩ B. Everyday "coffee or tea" is usually exclusive, but the mathematical ∪ is not. Press A ∪ B in the Venn tool above and you will see the overlapping middle light up along with everything else.

If you want an exclusive or, you need the symmetric difference: A △ B = (A\B) ∪ (B\A). That is XOR.

Set difference is not symmetric

A \ B ≠ B \ A. From the example above, A\B = {1,2} while B\A = {5,6}. ∪ and ∩ commute. The backslash does not.

Set difference is not associative either

A \ (B \ C) ≠ (A \ B) \ C in general. Counterexample: A={1,2}, B={2}, C={2}. On the left, B\C = ∅ so you get A\∅ = {1,2}. On the right, {1}\{2} = {1}. So whenever more than one difference shows up, rewrite every one of them as ∩ Bc before you start. Once only ∩ and ᶜ remain, associativity comes back.

Complement has a hidden argument

Ac is really Ω \ A. It is an operation that depends on Ω, and the notation hides that dependency completely. Any exam problem that swaps the sample space midway will collect points here. Always check what Ω is right now before you take a complement.

예제 5.1 — 식 단순화

다음을 최대한 간단히 해. (시험에 딱 이 형태로 나오는 유형)

(a) (A ∪ B) ∩ (A ∪ Bc)     (b) (A ∩ B) ∪ (A ∩ Bc)     (c) (Ac ∪ Bc)c

풀이

(a) 분배법칙(∪ 버전)을 거꾸로 쓴다:

(A∪B) ∩ (A∪Bc) = A ∪ (B ∩ Bc) = A ∪ ∅ = A

(b) 이번엔 ∩ 버전 분배법칙:

(A∩B) ∪ (A∩Bc) = A ∩ (B ∪ Bc) = A ∩ Ω = A

(b)는 말로 하면 이래: "A이면서 B" 와 "A이면서 B 아님"을 합치면 그냥 "A". 당연하지. 그리고 이 두 조각은 서로소야. 이게 Module 3에서 P(A) = P(A∩B) + P(A∩Bc) 라는 law of total probability의 씨앗이야. 이 예제는 그냥 연습문제가 아니라 나중에 계속 쓰게 될 도구야.

(c) De Morgan을 두 번:

(Ac ∪ Bc)c = (Ac)c ∩ (Bc)c = A ∩ B
Example 5.1 — simplifying expressions

Simplify each of these as far as it will go. Exams use exactly this format.

(a) (A ∪ B) ∩ (A ∪ Bc)     (b) (A ∩ B) ∪ (A ∩ Bc)     (c) (Ac ∪ Bc)c

Solution

(a) Run the distributive law (∪ version) backwards:

(A∪B) ∩ (A∪Bc) = A ∪ (B ∩ Bc) = A ∪ ∅ = A

(b) Same move, ∩ version this time:

(A∩B) ∪ (A∩Bc) = A ∩ (B ∪ Bc) = A ∩ Ω = A

In words, (b) says: take "A and B" together with "A and not B" and you are left with plain "A". Obvious enough. What matters is that those two pieces are disjoint. That is the seed of P(A) = P(A∩B) + P(A∩Bc), the law of total probability in Module 3. This example is not a drill, it is a tool you will keep reaching for.

(c) De Morgan twice:

(Ac ∪ Bc)c = (Ac)c ∩ (Bc)c = A ∩ B

산수의 직관을 그대로 옮기면 반쯤 틀린다

숫자에서는 a×(b+c) = ab+ac는 되지만 a+(b×c) ≠ (a+b)×(a+c)야. 한쪽만 분배돼. 그런데 집합에서는 ∩도 ∪도 서로에게 분배돼. 양방향이야. 그래서 "∩이 곱셈, ∪가 덧셈"이라는 비유는 절반만 맞고, 이 절반이 시험에서 틀리게 만들어. 비유 대신 벤 다이어그램을 그려.

De Morgan에서 연산 뒤집는 걸 까먹는 것

(A∩B)c = Ac∩Bc ← 틀렸다. 반례를 바로 만들 수 있어. Ω={1,2}, A={1}, B={2}라 하면 A∩B=∅이니 좌변은 ∅c=Ω={1,2}. 우변은 Ac∩Bc = {2}∩{1} = ∅. 전혀 다르지. 반례 하나 만들어보는 게 열 번 외우는 것보다 오래 가.

"증명하라"는 벤 다이어그램을 요구하는 게 아니다

HW1 Problem 2에 "use an element-wise argument"라고 명시돼 있어. 즉 x ∈ Ω를 하나 잡고 x ∈ LHS ⟺ x ∈ RHS를 보여야 해. 벤 다이어그램은 확인 도구지 증명이 아니야 (특히 집합이 4개 이상이면 평면에 못 그려). 시험에서도 "prove"라고 쓰여 있으면 원소를 잡고 시작해.

템플릿은 이래: "(⊆ 방향) x ∈ (A∪B)c라 하자. 그러면 x ∉ A∪B이므로 x ∉ A이고 x ∉ B. 따라서 x ∈ Ac이고 x ∈ Bc, 즉 x ∈ Ac∩Bc. (⊇ 방향) 위 단계를 거꾸로 …" 각 단계가 ⟺ 이면 한 방향만 쓰고 "모든 단계가 동치"라고 적어도 돼.

Trap

Arithmetic intuition is only half right here

With numbers, a×(b+c) = ab+ac holds but a+(b×c) ≠ (a+b)×(a+c). Only one direction distributes. With sets, ∩ and ∪ each distribute over the other. Both directions. So the "∩ is multiplication, ∪ is addition" analogy is exactly half correct, and it is the wrong half that costs marks. Draw the Venn diagram instead of leaning on the analogy.

Forgetting to flip the operation in De Morgan

(A∩B)c = Ac∩Bc ← wrong. A counterexample takes seconds. Let Ω={1,2}, A={1}, B={2}. Then A∩B=∅, so the left side is ∅c=Ω={1,2}, while the right side is Ac∩Bc = {2}∩{1} = ∅. Nothing alike. Building one counterexample sticks longer than ten repetitions.

"Prove" does not mean "draw a Venn diagram"

HW1 Problem 2 says "use an element-wise argument" in so many words. Take an x ∈ Ω and show x ∈ LHS ⟺ x ∈ RHS. A Venn diagram is a checking device, not a proof, and past four sets it cannot even be drawn in the plane. Whenever an exam says "prove", start by grabbing an element.

The template runs like this: "(⊆ direction) Suppose x ∈ (A∪B)c. Then x ∉ A∪B, so x ∉ A and x ∉ B. Hence x ∈ Ac and x ∈ Bc, that is x ∈ Ac∩Bc. (⊇ direction) Run the same steps backwards …" If every step is an ⟺ you may write one direction only and state that all steps are equivalences.

Finite, countable, uncountable

Definition 10–12. 이 모듈에서 제일 미묘하고, 제일 중요한 구분.

Definitions 10–12. The subtlest distinction in this module, and the one that matters most.

Definition 10 — Finite

원소 개수가 유한한 집합. 예: Ω = {1,2,3,4,5,6}

Definition 10 — Finite

A set with finitely many elements. Example: Ω = {1,2,3,4,5,6}

Definition 11 — Countably infinite

원소들을 양의 정수와 일대일 대응시킬 수 있는 무한집합. 즉 1번, 2번, 3번, … 하고 번호를 매겨서 빠짐없이 다 셀 수 있는 집합. 예: ℕ, ℤ, ℤ+, ℚ(유리수)

Definition 11 — Countably infinite

An infinite set whose elements can be put in one-to-one correspondence with the positive integers. Tag them first, second, third, and so on, and nothing gets left out. Examples: ℕ, ℤ, ℤ+, ℚ (the rationals).

Definition 12 — Uncountable

가산이 아닌 집합. 아무리 번호를 매겨도 반드시 빠지는 원소가 생긴다. 예: ℝ, [a,b], (a,b)

Definition 12 — Uncountable

A set that is not countable. However you assign the numbers, something always gets missed. Examples: ℝ, [a,b], (a,b)

"셀 수 있다"는 게 무슨 뜻인지

What "countable" actually means

핵심은 줄 세우기야. 집합의 원소들을 한 줄로 세워서, 어떤 원소를 지목하든 "얘는 몇 번째"라고 유한한 시간 안에 답할 수 있으면 가산이야.

It comes down to forming a queue. Line the elements up, and if you can answer "which position is this one in?" in finite time for any element someone points at, the set is countable.

예제 6.1

다음 각각이 finite / countably infinite / uncountable 중 무엇인지 판정해.

  1. 주사위 100번 굴린 결과의 모든 가능한 수열
  2. 동전을 앞면이 나올 때까지 던졌을 때 걸린 횟수의 집합
  3. 동전을 무한히 던졌을 때 나올 수 있는 모든 수열의 집합
  4. {1/n : n ∈ ℕ}
  5. 구간 [0, 0.001]
풀이
  1. Finite. 6100개. 엄청 크지만 유한해. 크다 ≠ 무한하다.
  2. Countably infinite. {1, 2, 3, …} = ℕ이야. 몇 번이든 걸릴 수 있지만 각 결과에 번호가 붙어.
  3. Uncountable. 각 수열을 H=0, T=1로 읽으면 (0,1) 구간의 이진 소수와 대응돼. 대각선 논법이 그대로 적용돼. 2번과 3번의 차이를 잘 봐. "언제 멈추는가"는 가산이지만 "무한히 계속되는 패턴 전체"는 비가산이야.
  4. Countably infinite. 1, 1/2, 1/3, …로 번호가 자연스럽게 붙어. 원소들이 0에 무한히 몰려있어도 가산이야.
  5. Uncountable. 길이가 0.001밖에 안 되지만 [0,1]과 같은 크기야 (선형 축소로 일대일 대응이 되니까).
Example 6.1

Classify each of these as finite, countably infinite, or uncountable.

  1. Every possible sequence of outcomes from rolling a die 100 times
  2. The set of possible counts of how many flips it took to get the first head
  3. The set of all sequences you could get from flipping a coin forever
  4. {1/n : n ∈ ℕ}
  5. The interval [0, 0.001]
Solution
  1. Finite. There are 6100 of them. Enormous, but finite. Large is not the same as infinite.
  2. Countably infinite. It is {1, 2, 3, …} = ℕ. It could take any number of flips, but every outcome gets a number.
  3. Uncountable. Read each sequence with H=0, T=1 and it becomes a binary expansion of a number in (0,1). The diagonal argument applies directly. Compare 2 and 3 carefully. "When does it stop" is countable, but "every infinite pattern" is not.
  4. Countably infinite. The numbering falls out on its own: 1, 1/2, 1/3, …. Elements piling up near 0 does not make it uncountable.
  5. Uncountable. It is only 0.001 wide, and it is still the same size as [0,1], since a linear rescaling puts them in one-to-one correspondence.
함정 · 여기가 제일 헷갈린다

무한 ≠ 비가산

슬라이드에 이렇게 쓰여 있어: "모든 비가산 집합은 무한하다. 그러나 모든 무한 집합이 비가산인 건 아니다." 대표적 반례가 ℚ(유리수)야. 유리수는 실수 안에 촘촘히 박혀 있어서 "연속적"으로 보이지만 가산이야. 두 정수의 비 p/q로 표에 배열해서 대각선으로 훑으면 다 셀 수 있거든.

크기(길이)와 가산성은 무관하다

(0, 0.0001)은 짧지만 비가산. ℤ는 무한히 뻗어있지만 가산. "얼마나 넓은가"가 아니라 "번호를 매길 수 있는가"가 기준이야.

왜 이걸 배우는지 (진짜 이유)

Ω가 유한하거나 가산이면 2Ω의 모든 부분집합에 확률을 줄 수 있어서 아무 문제가 없어. 그런데 Ω가 비가산이면(예: [0,1]에서 아무 숫자나 뽑기) 모든 부분집합에 일관되게 확률을 부여하는 게 수학적으로 불가능해져. 그래서 확률을 줄 수 있는 사건만 골라 모은 σ-algebra ℱ가 필요해지는 거야.

즉 이 섹션은 Module 2에서 σ-algebra가 왜 갑자기 튀어나오는지에 대한 답이야. HW1 Problem 4가 σ-algebra 문제인데, "왜 power set 놔두고 이런 걸 정의하나"에 대한 대답이 여기 있어. 지금은 "비가산 때문이다" 정도만 기억해두면 돼.

Trap · the most confusing part of this module

Infinite does not mean uncountable

The slide states it plainly: "every uncountable set is infinite, but not every infinite set is uncountable." The standard counterexample is ℚ, the rationals. They sit densely inside the reals and look "continuous", yet they are countable. Arrange them in a grid by numerator and denominator p/q, sweep the diagonals, and you have counted all of them.

Size and countability have nothing to do with each other

(0, 0.0001) is tiny and uncountable. ℤ runs forever and is countable. The test is not "how wide is it" but "can it be numbered".

Why any of this is here (the real reason)

When Ω is finite or countable you can hand a probability to every subset in 2Ω and nothing breaks. When Ω is uncountable, say picking a real number out of [0,1], assigning a consistent probability to every subset becomes mathematically impossible. That is what forces you to keep only the subsets you can measure, collected into a σ-algebra ℱ.

So this section is the answer to why a σ-algebra suddenly appears in Module 2. HW1 Problem 4 is a σ-algebra problem, and the answer to "why define this instead of just using the power set" lives here. For now, "because of uncountability" is enough to carry forward.

Power Set

Definition 13. 가능한 모든 질문을 한 자루에 담기.

Definition 13. Every question you could ask, gathered into one bag.

Definition 13

Ω의 멱집합(power set) 2Ω는 Ω의 모든 부분집합을 원소로 갖는 집합이다.

2Ω = {A : A ⊆ Ω}
Definition 13

The power set of Ω, written 2Ω, is the set whose elements are all the subsets of Ω.

2Ω = {A : A ⊆ Ω}

02번에서 "질문 하나 = 부분집합 하나"라고 했지. 그러면 2Ω는 이 실험에 대해 던질 수 있는 모든 질문의 모음이야. 슬라이드 표현으로는 "encodes all possible questions about the outcome".

Section 02 established that one question equals one subset. Put those together and 2Ω is the collection of every question you could ask about this experiment. The slide phrases it as "encodes all possible questions about the outcome".

왜 하필 기호가 2Ω 인가

Why the symbol is 2Ω

이름이 이상해 보이는데, 이유가 있어. 그리고 이 이유가 컴공 배경이면 바로 와닿을 거야.

The notation looks odd until you see where it comes from, and with a computer engineering background it lands immediately.

예제 7.1

(a) Ω = {1, 2}의 멱집합을 모두 써라.   (b) Ω = {1,2,3,4}일 때 |2Ω|는?   (c) Ω의 원소가 10개면?

풀이

(a) 2Ω = {∅, {1}, {2}, {1,2}} — 4개. ∅과 Ω 자신을 빼먹지 마. 제일 흔한 실수야.

(b) 24 = 16. HW1 Problem 4(d)가 정확히 이 질문이야.

(c) 210 = 1024. 원소 10개짜리 실험에 대해 던질 수 있는 서로 다른 질문이 1024개라는 뜻이야.

Example 7.1

(a) Write out the whole power set of Ω = {1, 2}.   (b) For Ω = {1,2,3,4}, what is |2Ω|?   (c) And if Ω has 10 elements?

Solution

(a) 2Ω = {∅, {1}, {2}, {1,2}}, four of them. Do not drop ∅ or Ω itself. That is the single most common slip.

(b) 24 = 16. HW1 Problem 4(d) asks exactly this.

(c) 210 = 1024, meaning there are 1024 distinct questions you can ask about an experiment with 10 outcomes.

함정

2^Ω 의 원소는 "집합"이지 "숫자"가 아니다

Ω = {1,2,3}일 때:

  • {1} ∈ 2Ω ✓  /  1 ∈ 2Ω ✗
  • {1} ⊆ Ω ✓  /  {1} ∈ Ω ✗

레벨이 한 칸 올라간 거야. Ω의 원소는 결과(outcome)고, 2Ω의 원소는 사건(event)이야. 시험에서 ∈/⊆ 판정 문제가 나오면 "지금 얘기하는 집합의 원소가 뭐지?"를 먼저 물어봐.

∅ 과 Ω 도 멱집합의 원소다

둘 다 Ω의 부분집합이니까 당연히 들어가. ∅은 "절대 안 일어나는 사건", Ω는 "반드시 일어나는 사건"이야. 확률로 치면 0과 1.

Ω가 무한하면 2^Ω 는 급격히 커진다

Ω = ℕ처럼 가산무한이어도 2Ω는 비가산이 돼. (부분집합 하나 = 무한 이진 수열 하나 = 06번 예제 6.1의 3번) 그래서 무한 표본공간에서는 멱집합 전체를 사건 모음으로 쓰는 게 부담스러워지고, 여기서 σ-algebra가 등장해. Module 2에서 바로 이어져.

Trap

The elements of 2^Ω are sets, not numbers

With Ω = {1,2,3}:

  • {1} ∈ 2Ω ✓  /  1 ∈ 2Ω ✗
  • {1} ⊆ Ω ✓  /  {1} ∈ Ω ✗

You have moved up one level. The elements of Ω are outcomes; the elements of 2Ω are events. Whenever an exam asks you to judge an ∈ or ⊆ statement, first ask "what are the elements of the set I am talking about right now?"

∅ and Ω are elements of the power set too

Both are subsets of Ω, so of course they are in there. ∅ is the event that never happens and Ω is the event that always happens. In probability terms, 0 and 1.

An infinite Ω blows the power set up fast

Even when Ω = ℕ is only countably infinite, 2Ω comes out uncountable. One subset is one infinite binary sequence, which is item 3 of Example 6.1. So on an infinite sample space, using the entire power set as your event collection becomes unworkable, and that is exactly where the σ-algebra walks in. Module 2 picks this up directly.

Index sets and infinite operations

Definition 14. 집합이 두세 개가 아니라 무한히 많을 때의 표기법.

Definition 14. Notation for when you have infinitely many sets instead of two or three.

Definition 14

집합 I가 있을 때, {Ai : i ∈ I}를 I로 인덱싱된 집합족(indexed family)이라 하고, I를 인덱스 집합(index set)이라 한다.

Definition 14

Given a set I, the collection {Ai : i ∈ I} is a family indexed by I, and I is called the index set.

이건 사실 새로운 개념이 아니라 표기법이야. 코드로 치면 배열 인덱스랑 똑같아. A[i]에서 i가 돌 수 있는 범위가 I인 거지. 다만 I가 유한할 필요도, 정수일 필요도 없어.

This is notation, not a new idea. In code it is an array index: in A[i], the range that i is allowed to run over is I. The only difference is that I need not be finite, and need not be made of integers.

인덱스 집합표기이 과목/전공에서 어디에 쓰이나

무한 개의 합집합과 교집합

Unions and intersections over infinitely many sets

⋃i∈I Ai = {ω : 적어도 하나의 i에 대해 ω ∈ Ai} "어느 하나라도 걸리면 통과" · OR의 무한 버전
⋃i∈I Ai = {ω : ω ∈ Ai for at least one i} passes if it lands in any one of them · OR, extended to infinity
⋂i∈I Ai = {ω : 모든 i에 대해 ω ∈ Ai} "전부 다 통과해야 통과" · AND의 무한 버전
⋂i∈I Ai = {ω : ω ∈ Ai for every i} has to clear all of them · AND, extended to infinity
예제 8.1

다음 무한 합집합/교집합을 구해.

  1. An = [0, 1 − 1/n], n ∈ ℕ 일 때 ⋃n An
  2. Bn = (−1/n, 1/n) 일 때 ⋂n Bn
  3. Cn = {n, n+1, n+2, …} 일 때 ⋂n Cn
풀이
  1. [0, 1). 각 An은 닫힌 구간인데 합집합은 열린 구간이 됐어. 1에 얼마든지 가까워지지만 1 자체는 어떤 An에도 없거든.
  2. {0}. 열린 구간들의 교집합인데 결과는 닫힌 집합(한 점)이야. 0은 모든 Bn에 들어있고, 0이 아닌 x는 1/n < |x|가 되는 n부터 탈락해.
  3. ∅. 어떤 자연수 k를 잡아도 Ck+1에는 안 들어있어. 이게 HW1 Problem 7(e)야. 거기선 An = {n, n+1, …}로 나오고, 이어서 lim P(An) = P(∅) = 0임을 확인해서 continuity of probability를 검증하게 돼.
Example 8.1

Work out each infinite union or intersection.

  1. An = [0, 1 − 1/n] for n ∈ ℕ: find ⋃n An
  2. Bn = (−1/n, 1/n): find ⋂n Bn
  3. Cn = {n, n+1, n+2, …}: find ⋂n Cn
Solution
  1. [0, 1). Each An is a closed interval, yet the union comes out open. You get arbitrarily close to 1, but 1 itself is in no An.
  2. {0}. An intersection of open intervals producing a closed set, a single point. 0 belongs to every Bn, while any nonzero x drops out as soon as 1/n < |x|.
  3. ∅. Whatever natural number k you pick, it is missing from Ck+1. This is HW1 Problem 7(e). There it appears as An = {n, n+1, …}, and you then check lim P(An) = P(∅) = 0 to verify continuity of probability.
함정

유한에서 참인 게 무한에서 깨진다

위 예제가 전부 그 얘기야. 열린 집합들의 무한 교집합이 닫힐 수 있고, 닫힌 집합들의 무한 합집합이 열릴 수 있어. 유한 개면 절대 안 그래. 그래서 무한 연산이 나오면 "유한할 때랑 같겠지"라고 넘기지 말고 극한을 직접 확인해야 해.

"모든 n에 대해 비어있지 않다" ≠ "교집합이 비어있지 않다"

이게 위 함정의 정확한 형태야. An ≠ ∅이 모든 n에 대해 성립해도 ⋂n An = ∅일 수 있어. 각 집합이 비어있지 않다는 것과, 모두에 공통으로 들어있는 원소가 있다는 건 다른 얘기야.

인덱스 집합은 정수가 아니어도 된다

I = ℝ이면 집합이 비가산 개 있는 거야. 이때 ⋃t∈ℝ At는 집합으로는 잘 정의되지만, 확률에서는 이걸 함부로 쓸 수 없어. 확률의 additivity 공리는 가산 개까지만 보장하거든. Module 2에서 "countable additivity"라고 countable을 굳이 붙여 쓰는 이유가 이거야.

Trap

What holds for finitely many breaks for infinitely many

All three parts of the example above make this point. An infinite intersection of open sets can be closed, and an infinite union of closed sets can be open. Neither ever happens with finitely many. So when an infinite operation shows up, do not assume it behaves like the finite case. Check the limit.

"Every An is nonempty" does not give "the intersection is nonempty"

This is the precise form of the trap above. An ≠ ∅ can hold for every n while ⋂n An = ∅. "Each set has something in it" and "there is something common to all of them" are different claims.

An index set does not have to be integers

Take I = ℝ and you have uncountably many sets. As a set operation, ⋃t∈ℝ At is perfectly well defined, but you cannot use it freely in probability. The additivity axiom only guarantees countably many. That is why Module 2 spells it out as "countable additivity" rather than just "additivity".

Partition

이 모듈의 결승선. 앞으로 계속 쓰게 될 개념.

The finish line of this module, and a concept you will keep using.

정의 — 두 조건

집합족 {Ai : i ∈ I}가 Ω의 분할(partition)이라는 건 다음 두 가지를 동시에 만족한다는 뜻:

① Ai ∩ Aj = ∅   (i ≠ j) 겹치지 않는다
② ⋃i∈I Ai = Ω        빈틈이 없다
Definition — two conditions

A family {Ai : i ∈ I} is a partition of Ω when it satisfies both of these at the same time:

① Ai ∩ Aj = ∅   (i ≠ j) no overlap
② ⋃i∈I Ai = Ω        no gaps

한 마디로 "Ω를 겹침도 빈틈도 없이 조각낸 것"이야. 결과 ω가 무엇이든, 정확히 하나의 조각에만 들어가.

In one phrase, Ω cut into pieces with no overlaps and no gaps. Whatever outcome ω turns up, it lands in exactly one piece.

예제 9.1 — HW1 Problem 3 유형

패킷을 두 번 연속 전송한다. 각 전송은 성공(S) 또는 실패(F).

  1. 표본공간 Ω를 구성해라.
  2. A = {정확히 한 번 성공}을 Ω의 부분집합으로 써라.
  3. B = {적어도 한 번 성공}을 써라.
  4. A0, A1, A2를 성공 횟수 0, 1, 2회로 정의할 때 이게 분할임을 보여라.
풀이

1. Ω = {SS, SF, FS, FF} — 4개. SF와 FS를 반드시 구별해야 해. 첫 번째 전송이 성공하고 두 번째가 실패한 것과, 그 반대는 다른 결과야.

2. A = {SF, FS}

3. B = {SS, SF, FS}. "적어도 한 번"은 {FF}c로 구하는 게 빨라. 여집합으로 접근하는 습관을 들여.

4. A0 = {FF}, A1 = {SF, FS}, A2 = {SS}. 두 조건을 각각 확인:

  • ① 서로소: A0∩A1 = ∅, A0∩A2 = ∅, A1∩A2 = ∅. 세 쌍을 전부 확인해야 해.
  • ② 덮음: A0∪A1∪A2 = {FF, SF, FS, SS} = Ω ✓

더 깔끔한 논증도 가능해. "각 결과는 성공 횟수가 정확히 하나로 정해지고, 그 값은 0, 1, 2 중 하나다." 이 한 문장이 두 조건을 동시에 함의해. 일반적으로, 각 결과에 값을 하나씩 붙이는 함수를 만들면 그 함수의 값에 따른 분류가 자동으로 분할이 돼. (이게 나중에 확률변수의 정의로 이어져.)

(e) 왜 분할이 유용한가 — 문제에 서술형으로 나오는 부분인데, 답은 이거야. 분할이 있으면 복잡한 사건의 확률을 조각별로 나눠 더할 수 있어. 조각들이 서로소니까 겹쳐서 두 번 세는 일이 없고, 전체를 덮으니까 빠뜨리는 것도 없거든. P(B) = Σi P(B ∩ Ai) 라는 law of total probability가 정확히 이걸 하는 거야.

Example 9.1 — the HW1 Problem 3 pattern

You transmit a packet twice in a row. Each transmission either succeeds (S) or fails (F).

  1. Build the sample space Ω.
  2. Write A = {exactly one success} as a subset of Ω.
  3. Write B = {at least one success}.
  4. Define A0, A1, A2 by the number of successes being 0, 1, 2 and show these form a partition.
Solution

1. Ω = {SS, SF, FS, FF}, four outcomes. SF and FS have to stay distinct. First succeeds then fails is a different outcome from the reverse.

2. A = {SF, FS}

3. B = {SS, SF, FS}. The fast route to "at least one" is {FF}c. Build the habit of reaching for the complement.

4. A0 = {FF}, A1 = {SF, FS}, A2 = {SS}. Check both conditions:

  • ① pairwise disjoint: A0∩A1 = ∅, A0∩A2 = ∅, A1∩A2 = ∅. All three pairs, not just one.
  • ② covering: A0∪A1∪A2 = {FF, SF, FS, SS} = Ω ✓

There is a cleaner argument available: "each outcome has exactly one success count, and that count is 0, 1 or 2." That single sentence implies both conditions at once. In general, any function that assigns one value to each outcome automatically partitions Ω by its value. That idea is what later becomes the definition of a random variable.

(e) Why partitions are useful — the problem asks for this in prose, and the answer is: with a partition in hand you can split a complicated event's probability into pieces and add them up. The pieces are disjoint so nothing gets counted twice, and they cover everything so nothing is missed. The law of total probability, P(B) = Σi P(B ∩ Ai), is exactly this move.

함정 · 시험 단골

서로소인데 분할이 아닌 경우

Ω = {1,…,6}에서 {{1}, {2}}는 서로소지만 분할이 아니야. 3,4,5,6이 안 덮였잖아. 조건 ①만 확인하고 넘어가는 게 제일 흔한 실수야.

덮는데 분할이 아닌 경우

{{1,2,3}, {3,4,5,6}}는 Ω 전체를 덮지만 3이 양쪽에 있어서 분할이 아니야. 확률로 치면 3을 두 번 세게 돼.

pairwise disjoint 와 "전체 교집합이 공집합"은 다르다

이게 진짜 함정이야. 세 집합 A={1,2}, B={2,3}, C={3,1}을 보자.

  • A∩B∩C = ∅ ← 셋 다 공통인 원소는 없다
  • 그런데 A∩B = {2} ≠ ∅ ← pairwise disjoint가 아니다!

분할의 조건 ①이 요구하는 건 pairwise야. 즉 모든 두 개씩의 쌍이 서로소여야 해. 전체 교집합이 비었는지만 보면 안 돼. 집합이 n개면 확인할 쌍이 n(n−1)/2개야.

∅ 은 보통 분할의 조각에 넣지 않는다

∅을 조각으로 끼워 넣어도 두 조건은 기술적으로 만족돼(∅ ∩ A = ∅이고 합집합도 안 변하니까). 하지만 의미가 없어서 대부분의 교재는 각 조각이 비어있지 않다고 가정해. 시험에서 "이게 분할인가?"를 물으면 이 문제로 트집 잡지는 않을 거야. 다만 정의를 쓸 때는 짚고 넘어가면 좋아.

Trap · shows up on exams constantly

Disjoint but not a partition

In Ω = {1,…,6}, the family {{1}, {2}} is disjoint but is not a partition, since 3, 4, 5, 6 are uncovered. Checking only condition ① and moving on is the most common mistake here.

Covering but not a partition

{{1,2,3}, {3,4,5,6}} covers all of Ω, but 3 sits in both pieces, so it is not a partition. In probability terms you would count 3 twice.

Pairwise disjoint is not "the total intersection is empty"

This is the real trap. Take A={1,2}, B={2,3}, C={3,1}.

  • A∩B∩C = ∅ ← no element is common to all three
  • and yet A∩B = {2} ≠ ∅ ← not pairwise disjoint!

Condition ① demands pairwise disjointness, meaning every pair must be disjoint. Checking whether the total intersection is empty is not the same test. With n sets you have n(n−1)/2 pairs to check.

∅ is normally not allowed as a piece

Throwing ∅ in as an extra piece technically satisfies both conditions, since ∅ ∩ A = ∅ and the union does not change. It just carries no meaning, so most texts assume every piece is nonempty. An exam asking "is this a partition?" is unlikely to hinge on this, but it is worth stating when you write the definition out.
